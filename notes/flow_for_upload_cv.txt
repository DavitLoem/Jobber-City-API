ប្រសិនបើយើង Upload File នោះទៅ Cloudinary ហើយ Save URL ចូល Database ភ្លាមៗ មុនពេល AI បញ្ជាក់ថាវាជា CV ពិតប្រាកដ នោះយើងនឹងខាតបង់ទំហំ Cloudinary ដោយសារតែឯកសារសម្រាម (ឧទាហរណ៍៖ គេ Upload រូបភាព ឬវិក្កយបត្រ) ហើយ Database របស់អ្នកក៏នឹងជាប់ URL ដែលមិនមែនជា CV ដែរ។

វិធីដែលត្រឹមត្រូវ និងមានស្តង់ដារបំផុត គឺយើងត្រូវឱ្យ AI វិភាគសិន។ បើវាជា CV ពិតប្រាកដ ទើបយើង Upload ទៅ Cloudinary។ ខាងក្រោមនេះជា Flow ដែលមានសុវត្ថិភាព និងងាយស្រួលយល់បំផុត (The Optimal Flow)៖

-ជំហានទី ១៖ ការជ្រើសរើសឯកសារ (Select Document)
នៅលើ Mobile App: នៅអេក្រង់ Profile មានប៊ូតុងមួយឈ្មោះថា "Upload CV / Auto-Fill Profile"។

នៅពេល Seeker ចុចប៊ូតុងនេះ កម្មវិធីនឹងបើក File Picker ដើម្បីឱ្យគាត់រើសឯកសារ (កំណត់យកតែ .pdf)។

-ជំហានទី ២៖ អេក្រង់កំពុងវិភាគ (Scanning UI & Backend Processing)
នៅលើ Mobile App: ពេលរើស File រួច កម្មវិធីនឹងលោតទៅអេក្រង់ថ្មីមួយ (ឬ Pop-up ធំមួយ) ដែលមាន Animation វិលៗ ឬរូបរ៉ាដាស្កេន ហើយមានអក្សរលោតប្តូរគ្នា (ឧ. "កំពុងអានឯកសារ...", "កំពុងស្រង់បទពិសោធន៍...", "ជិតរួចរាល់ហើយ...")។

នៅពីក្រោយខ្នង (Backend API POST /api/cv/extract): ពេលនេះ Mobile App កំពុងបាញ់ File ទៅ Backend។

Backend ទាញយកអត្ថបទចេញពី PDF។

បញ្ជូនអត្ថបទនោះទៅកាន់ Gemini។

Gemini ឆែកសិន៖ តើនេះជា CV មែនទេ?

បើមិនមែន (is_cv: false): Backend បោះ Error ទៅ App វិញភ្លាមៗថា "ឯកសារនេះមិនមែនជាប្រវត្តិរូបសង្ខេបទេ" (App បិទឡូហ្គូស្កេន ហើយបង្ហាញសារក្រហម)។

បើពិតជា CV មែន (is_cv: true): Gemini ចាប់ផ្តើមបំបែកទិន្នន័យជា JSON។

Upload & Save: ដោយសារយើងដឹងច្បាស់ថាវាជា CV ពិតមែន Backend នឹងធ្វើការ Upload វាទៅ Cloudinary យក URL ទៅ Save ចូល resume_url ក្នុង Database (ដើម្បីឱ្យគាត់មាន CV សម្រាប់ Apply ការងារ)។

Backend បោះ JSON ទិន្នន័យ (Experience, Education, Skills) ត្រឡប់មក Mobile App វិញ។

-ជំហានទី ៣៖ ការសម្រេចចិត្ត (Prompt to Auto-Fill)
នៅលើ Mobile App: អេក្រង់ស្កេនប្តូរទៅជាសញ្ញា ✓ ពណ៌បៃតង (Upload ជោគជ័យ)។

បន្ទាប់មក App លោតផ្ទាំងសួរគាត់ថា៖ "យើងបានរកឃើញ បទពិសោធន៍ការងារ (៣) និង ការអប់រំ (២) នៅក្នុង CV របស់អ្នក។ តើអ្នកចង់ទាញយកទិន្នន័យទាំងនេះទៅបំពេញក្នុង Profile របស់អ្នកដោយស្វ័យប្រវត្តិឬទេ?"

ប៊ូតុង "ទេ, អរគុណ" (Skip): បិទផ្ទាំងនេះ ហើយត្រឡប់ទៅអេក្រង់ Profile ដើម (គាត់បានត្រឹម Upload CV ចូលប្រព័ន្ធ តែមិនបានរៀបចំ Profile ទេ)។

ប៊ូតុង "បន្តការផ្ទៀងផ្ទាត់" (Review & Add): ចាប់ផ្តើមចូលជំហានទី ៤។

-ជំហានទី ៤៖ លំហូរផ្ទៀងផ្ទាត់ និងរក្សាទុក (The Review Flow)
ពេលគាត់ចុចបន្ត កម្មវិធីនឹងរក្សាទុក JSON នោះក្នុងអថេរបណ្ដោះអាសន្ន។

កម្មវិធីនឹងលោតទៅអេក្រង់ "Review Data" (ឬវាអាចបើកអេក្រង់ Add Experience ដែលយើងមានស្រាប់តែម្តង) ដោយទាញទិន្នន័យពី JSON មកចាក់បញ្ចូលក្នុងប្រអប់នីមួយៗឱ្យហើយ។

គាត់មើលថាខុសឬត្រូវ រួចចុច "Save"។ ពេលគាត់ចុច Save, កម្មវិធីនឹងបាញ់ Request ទៅកាន់ API ចាស់ៗរបស់អ្នក (POST /api/seeker/experiences ។ល។) ដើម្បីធានាថាទិន្នន័យត្រូវបានរក្សាទុកយ៉ាងត្រឹមត្រូវតាមទម្រង់ស្តង់ដារ។

ដើម្បីឱ្យ Flow ថ្មីនេះដំណើរការ នៅក្នុង Backend យើងមិនចាំបាច់បង្កើតអ្វីថ្មីច្រើនទេ គឺយើងគ្រាន់តែកែប្រែ (Refactor) របស់ដែលមានស្រាប់ប៉ុណ្ណោះ។ នេះជា ៤ ចំណុចសំខាន់ៗដែលយើងត្រូវកែប្រែ៖

១. កែប្រែ AI Service (កន្លែងបញ្ជា Gemini)

អ្វីដែលត្រូវកែ៖ យើងត្រូវកែប្រែ Prompt (បញ្ជា) ដែលប្រាប់ទៅ Gemini ឱ្យចេះបែងចែកដាច់ស្រឡះថា "តើនេះជា CV ពិតប្រាកដឬអត់?"។ បើពិតមែន ត្រូវទាញទិន្នន័យមកជាទម្រង់ JSON ដ៏តឹងរ៉ឹងបំផុត (Strict JSON Format) ដែលមាន Key ត្រូវគ្នានឹង Database របស់យើងបេះបិទ។ បើមិនមែនទេ ត្រូវបោះ is_cv: false មកវិញ។

២. កែប្រែ Attachment Service (កន្លែងចាត់ចែងការ Upload)

អ្វីដែលត្រូវកែ៖ នៅក្នុងឯកសារ attachment_service.py យើងនឹងកែមុខងារ upload_and_parse_cv ឱ្យខ្លីជាងមុន។ វានឹងធ្វើការតែ ៤ ជំហានប៉ុណ្ណោះ៖ (១) ឆែកឯកសារ ➔ (២) ហៅ AI ឱ្យវិភាគ ➔ (៣) បើ AI ថាជា CV ពិតមែន ទើប Upload ទៅ Cloudinary រួច Update តែ resume_url ចូល Profile ➔ (៤) បោះ JSON ទិន្នន័យ (Experience, Education...) ត្រឡប់ទៅ Frontend វិញ ដោយមិន Save ពួកវាចូល Database ឡើយ។

៣. កែប្រែ Response Schema (ទម្រង់ទិន្នន័យបោះទៅ Frontend)

អ្វីដែលត្រូវកែ៖ យើងត្រូវបង្កើត Pydantic Schema ថ្មីមួយ (ឧទាហរណ៍ CvExtractionResponse) ដើម្បីប្រាប់សញ្ញាទៅកាន់ Frontend (Flutter) ថាវានឹងទទួលបានទិន្នន័យមានរាងរៅបែបណា (មាន List នៃ Experiences, Educations ជាដើម) ងាយស្រួលឱ្យ App ចាប់យកទៅប្រើ។

៤. ពិនិត្យមើល API Router

អ្វីដែលត្រូវកែ៖ យើងត្រូវពិនិត្យមើលកន្លែងដែលអ្នកប្រកាស Endpoint (ឧទាហរណ៍ @router.post("/upload-cv")) ដើម្បីធានាថាវាហៅ Service ត្រឹមត្រូវ និងប្រើ Schema ថ្មីដែលយើងទើបនឹងបង្កើត។
